## 🤖 AI models & prompts (inline audit — evidence from `ai_calls`)

- **`regional_places_research.v1` fails 45% on the API path** · `db/ai_prompts/regional_places_research.v1.yml`, `app/services/ai/anthropic_provider.rb` · impact 4 · effort 2 · conf 0.85 · **score 13.6** · **fix_kind: code** **[filed]**
  - Problem: 18 of 40 `provider: anthropic` calls failed (avg 97s). `max_tokens: 16000` non-streaming is in SDK-timeout/truncation territory (guidance: stream anything >~16K output); the provider (`Net::HTTP`, 300s read timeout, no streaming) returns whole-body-or-error.
  - Recommendation: inspect the `error` column on the failed `AiCall` rows; either stream (or chunk the research into two smaller calls), or reduce `max_tokens` + tighten the output contract. Historical `claude_cli` calls for the same slug ran 7+ min with failures too — this prompt needs a reliability pass whichever provider it's on.
- **Anthropic prompt cache is silently dead** · `app/services/ai/anthropic_provider.rb:18,91-96` · impact 3 · effort 1 · conf 0.9 · **score 13.5** · **fix_kind: code** **[filed]**
  - Problem: every `ai_calls` row shows `cache_read_input_tokens: 0`. `CACHE_MIN_SYSTEM_CHARS = 4000` (~1K tokens) was set against a "≈1,024 tokens" minimum, but the actual minimum cacheable prefix on Sonnet 4.6 is **2,048 tokens** (4,096 on Opus/Haiku 4.5) — `trip_structure.v1`'s ~5K-char system (~1.3K tokens) never clears it, so the `cache_control` marker is a documented no-op. The intended ~90% input savings never happened.
  - Recommendation: either accept and delete the dead code, or make it real: raise the gate to ~8,800 chars (2,048 tokens × 4.3 chars/tok) and move more static planning content (the schema/rules) into the system prompt so `trip_structure.v1` clears the minimum. Verify with `cache_creation_input_tokens`/`cache_read_input_tokens` in `/admin/ai_calls` after.
- **Sonnet 4.6 → Sonnet 5 migration** — covered by the trend lens below (score 9). Extra evidence from this audit: `AnthropicProvider#build_body` unconditionally sends `temperature` when set (`trip_concierge.v1` 0.4, `reservation_parse.v1` 0.1, `activity_narration.v1` 0.6, `nearby_ideas.v1` 0.4) — non-default sampling params **400 on Sonnet 5**, and adaptive thinking (on by default when `thinking` is omitted) will eat into each prompt's `max_tokens`. Migration = YAML model bump + provider guard for temperature + `thinking: {type: "disabled"}` (or raised budgets) + ~30% tokenizer re-baseline. Note: **intro pricing $2/$10 per MTok through 2026-08-31** makes Sonnet 5 *cheaper* than Sonnet 4.6 ($3/$15) right now.
- **Concierge chat doesn't stream** · `trip_concierge.v1` (avg ~7s, `max_tokens: 800`) · impact 3 · effort 3 · conf 0.7 · **score 6.3** · **[backlog]**
  - 7s of dead air per answer. Streaming SSE→Turbo Stream is the real fix; a cheap interim is dropping the concierge to `claude-haiku-4-5` (this is dossier-grounded Q&A, well within Haiku range, ~3× cheaper / ~2× faster). Pairs naturally with the agentic-concierge item.
- **Model placement is otherwise sound**: `activity_narration.v1` on Haiku 4.5 (high-volume, cheap) ✓; discovery prompts on Perplexity Sonar for fresh web data ✓ (seconds, not `claude_cli` minutes — the `ai_calls` table shows claude_cli `trip_structure` runs averaged **59 minutes** with 10/13 failures before the API migration); `place_hero_image` (gpt-image-2) is unwired, fine to leave.
